APK 端推荐方案：WebView 渲染轨 + 卡片正则直读管线
一、结论与理由
最推荐：原生 Kotlin 管线 + WebView 渲染，且管线直接读取卡 JSON 里的 regex_scripts——这正是“通用”的关键：
对比项	WebView 轨 ✅	纯 Compose 原生轨	
卡片模板复用	卡自带的 HTML 模板原样可用，零改写	每种模板都要手写原生组件	
新卡接入成本	零代码（读卡 JSON 即生效）	每种新标签写一遍 Compose	
复杂样式（羊皮纸/金线/渐变/折叠面板）	CSS 全支持，像素级还原	Canvas 手绘，工作量大	
滚动流畅度	面板多时需池化优化	原生流畅	
离线可用	✅（模板内联数据，无 CDN）	✅	
双轨混合是最终答案：未知卡片走 WebView 通用轨（自动），自家已知协议走 Compose 快速轨（高性能）。

二、核心代码（Kotlin，可直接进工程）
1. JS 正则字面量 → Kotlin Regex 转换器
卡里写的是 "/<S1>([\\s\\S]*?)<\\/S1>/gi" 这种 JS 格式，必须转换：
data class JsRegex(val pattern: String, val options: Set<RegexOption>)
fun parseJsRegex(literal: String): JsRegex? {
    val s = literal.trim()
    if (!s.startsWith("/")) return null
    val last = s.lastIndexOf('/')
    if (last <= 0) return null
    val flags = s.substring(last + 1)
    val opts = buildSet {
        if ('i' in flags) add(RegexOption.IGNORE_CASE)
        if ('s' in flags) add(RegexOption.DOT_MATCHES_ALL)
        if ('m' in flags) add(RegexOption.MULTILINE)
    }   // g 标志无需转换：Kotlin 的 replace/find 天然全局
    return JsRegex(s.substring(1, last), opts)
}
Java/JS 正则方言在本场景兼容：[\s\S]、非捕获组、惰性 *? 行为一致；\/ 在 Java 中合法。
2. 卡片脚本模型 + 渲染管线
import org.json.JSONObject
data class CardRegexScript(
    val id: String,
    val findRegex: String,
    val replaceString: String,
    val disabled: Boolean,
    val markdownOnly: Boolean,   // 显示层脚本 → 要用
    val promptOnly: Boolean,     // 提示词层脚本 → 渲染时跳过
    val minDepth: Int            // 与原卡语义一致：新楼层不受限
)
fun parseScripts(cardJson: JSONObject): List<CardRegexScript> =
    cardJson.optJSONObject("extensions")
        ?.optJSONArray("regex_scripts")
        ?.let { arr -> (0 until arr.length()).map { arr.getJSONObject(it) } }
        ?.map { j ->
            CardRegexScript(
                id = j.optString("id"),
                findRegex = j.optString("findRegex"),
                replaceString = j.optString("replaceString"),
                disabled = j.optBoolean("disabled", false),
                markdownOnly = j.optBoolean("markdownOnly", false),
                promptOnly = j.optBoolean("promptOnly", false),
                minDepth = j.optInt("minDepth", 0)
            )
        } ?: emptyList()
class RenderPipeline(scripts: List<CardRegexScript>) {
    /** 只取显示层脚本（markdownOnly 或两者皆非），跳过 promptOnly 与 disabled */
    private val compiled: List<Pair<Regex, String>> = scripts
        .filter { !it.disabled && !it.promptOnly }
        .mapNotNull { s ->
            parseJsRegex(s.findRegex)?.let { Regex(it.pattern, it.options) to s.replaceString }
        }
    /** 对单条消息执行全量替换，产出"显示用字符串" */
    fun render(messageText: String): String {
        var out = messageText
        for ((regex, template) in compiled) {
            out = regex.replace(out) { m -> substitute(template, m) }
        }
        return out
    }
    /** 处理 $1..$9 与 $& —— 用倒序避免 $10 误匹配 $1 */
    private fun substitute(template: String, m: MatchResult): String {
        var r = template.replace("$&", Matcher.quoteReplacement(m.value))
        for (i in m.groupValues.size - 1 downTo 1) {
            r = r.replace("\$$i", Matcher.quoteReplacement(m.groupValues[i]))
        }
        return r
    }
}
一张卡装上 RenderPipeline，它自带的 S1→羊皮纸面板、任何其他标签→任何面板全部自动生效——这就是“通用版”的本质：不自己实现面板，实现的是执行面板的引擎。
3. 分段器：纯文本段 vs HTML 面板段
sealed class Segment {
    data class Text(val content: String) : Segment()
    data class Html(val content: String) : Segment()
}
private val FENCE = Regex("```html\\s*\\n?([\\s\\S]*?)```", RegexOption.IGNORE_CASE)
fun segmentMessage(rendered: String): List<Segment> {
    val out = mutableListOf<Segment>()
    var last = 0
    for (m in FENCE.findAll(rendered)) {
        if (m.range.first > last)
            out += Segment.Text(rendered.substring(last, m.range.first).trim())
        out += Segment.Html(m.groupValues[1].trim())
        last = m.range.last + 1
    }
    if (last < rendered.length)
        out += Segment.Text(rendered.substring(last).trim())
    return out
}
4. 安全加固的 WebView + 高度自适应（Compose）
@Composable
fun PanelWebView(html: String, modifier: Modifier = Modifier) {
    var heightPx by remember { mutableStateOf(400) }
    val density = LocalDensity.current
    AndroidView(
        modifier = modifier
            .fillMaxWidth()
            .height(with(density) { heightPx.toDp() }),
        factory = { ctx ->
            WebView(ctx).apply {
                configureSecure(this)
                webViewClient = object : WebViewClient() {
                    override fun onPageFinished(view: WebView, url: String?) {
                        // JS 量取文档实际高度 → 回写 Compose 高度
                        view.evaluateJavascript(
                            "document.documentElement.scrollHeight"
                        ) { h -> h.toFloatOrNull()?.let { heightPx = it.toInt() } }
                    }
                }
            }
        },
        update = { wv ->
            wv.loadDataWithBaseURL(null, ensureDocument(html), "text/html", "utf-8", null)
        }
    )
}
/** 模板本身是完整文档就直接用；是片段则包一层 */
private fun ensureDocument(html: String): String =
    if (html.contains("<html", ignoreCase = true)) html else """
        <!doctype html><html><head><meta charset="utf-8">
        <meta name="viewport" content="width=device-width,initial-scale=1">
        <style>html,body{margin:0;padding:0;background:transparent}</style>
        </head><body>$html</body></html>"""
/** 安全锁死：面板模板只需内联 JS，其余全禁 */
private fun configureSecure(wv: WebView) = with(wv.settings) {
    javaScriptEnabled = true                        // 面板解析脚本需要
    allowFileAccess = false
    allowContentAccess = false
    allowUniversalAccessFromFileURLs = false
    domStorageEnabled = false
    cacheMode = WebSettings.LOAD_NO_CACHE
    wv.webViewClient = object : WebViewClient() {
        override fun shouldOverrideUrlLoading(v: WebView, r: WebResourceRequest) = true
        override fun shouldInterceptRequest(v: WebView, r: WebResourceRequest): WebResourceResponse? =
            if (r.url.scheme !in setOf("data", "about"))       // 拦截一切网络请求
                WebResourceResponse("text/plain", "utf-8", ByteArrayInputStream(ByteArray(0)))
            else null
    }
}
5. 消息气泡组装
@Composable
fun MessageBubble(rawText: String, pipeline: RenderPipeline) {
    val segments = remember(rawText, pipeline) {
        segmentMessage(pipeline.render(rawText))
    }
    Column(verticalArrangement = Arrangement.spacedBy(8.dp)) {
        segments.forEach { seg ->
            when (seg) {
                is Segment.Text -> MarkdownText(seg.content)   // 用 Markwon 渲染
                is Segment.Html -> PanelWebView(seg.content)
            }
        }
    }
}
6. 流式输出（打字机）挂起检测
/** 面板未闭合 → 尾部挂起，等 AI 写完再渲染，避免半截面板闪烁 */
fun splitPending(buffer: String): Pair<String, String> {
    val openFence = buffer.lastIndexOf("```html")
    val openTag   = buffer.lastIndexOf("<S1")
    val lastAny   = maxOf(openFence, openTag)
    if (lastAny == -1) return buffer to ""
    val closed = buffer.indexOf("```", openFence + 7).let { it > 0 } &&
                 (openFence == -1 || openTag == -1 || openTag < openFence)
    // 简化判定：取最后一段未闭合结构
    val pending = when {
        openTag > openFence && buffer.indexOf("</S1>", openTag) == -1 -> openTag
        openFence != -1 && buffer.indexOf("```", openFence + 7) == -1 -> openFence
        else -> -1
    }
    return if (pending == -1) buffer to ""
           else buffer.substring(0, pending) to buffer.substring(pending)
}
流式时把 pending 部分替换成“⚙ 档案同步中…”占位。
7. WebView 池（列表性能关键）
class WebViewPool(private val context: Context, private val max: Int = 4) {
    private val pool = ArrayDeque<WebView>()
    private val appCtx = context.applicationContext
    init {
        // Application.onCreate 里后台线程预热，消除首次 50~150ms 卡顿
        Thread { repeat(2) { precreate() } }.start()
    }
    private fun precreate() {
        val wv = WebView(appCtx).apply { configureSecure(this) }
        synchronized(pool) { pool.addLast(wv) }
    }
    fun obtain(): WebView = synchronized(pool) {
        pool.removeFirstOrNull() ?: WebView(appCtx).apply { configureSecure(this) }
    }
    fun recycle(wv: WebView) = synchronized(pool) {
        wv.loadDataWithBaseURL(null, "", "text/html", "utf-8", null)  // 清空降内存
        if (pool.size < max) pool.addLast(wv) else wv.destroy()
    }
}
8. 兜底：通用标签注册表（卡不带模板时用）
有些卡只有裸标签、没有 regex_scripts——注册一个内置模板兜底：
class TagRegistry {
    private val handlers = mutableMapOf<String, (String) -> String>()
    fun register(tag: String, renderer: (String) -> String) {
        handlers[tag.lowercase()] = renderer
    }
    /** 没有卡内模板时，走内置通用模板 */
    fun fallbackRender(text: String): String {
        var out = text
        for ((tag, renderer) in handlers) {
            out = Regex("<$tag>([\\s\\S]*?)</$tag>", RegexOption.IGNORE_CASE)
                .replace(out) { m -> renderer(m.groupValues[1]) }
        }
        return out
    }
}
// 使用：内置一个 S1 通用模板（内嵌第0节的 parseS1 + 渲染逻辑，从 assets 加载）
registry.register("S1") { raw ->
    ASSETS_BUILTIN_S1_TEMPLATE.replace("\$1", raw)
}
管线优先级：卡内 regex_scripts → 有则直接用；无 → TagRegistry 兜底。

四、性能与工程清单
#	问题	对策	
1	WebView 首次初始化 50~150ms	Application 启动时后台预热池	
2	长列表多面板卡顿	池化复用；或渲染完成后 draw() 截图为 Bitmap，列表里用 Image 显示、WebView 归池（快照模式）	
3	高度抖动	onPageFinished 里 JS 量高回写；模板根节点设固定宽、内容自适应	
4	面板模板含 <script>	JS 必须开，但 loadDataWithBaseURL(null,…) = 不透明源 + 拦截全部网络请求 = 零外联	
5	$10 误替换为 $1+0	替换倒序执行（代码已含）	
6	流式半截面板	splitPending 挂起未闭合结构	
7	用户数据安全	面板是展示层，永不执行业务逻辑；交互需求走 @JavascriptInterface 白名单暴露	
8	主题适配	模板全用 CSS 变量，注入 --bg1 等变量即可换肤	
9	内存	每次 recycle 时清空内容；低内存回调里收缩池	
五、什么时候用纯 Compose 原生轨
只有一种情况值得为特定协议写原生组件：该标签出现在几乎每条消息里（比如每楼都有 S1），此时原生渲染滚动更顺滑：
@Composable
fun S1PanelNative(d: S1Data) {          // parseS1 的 Kotlin 版数据类
    Card(colors = CardDefaults.cardColors(...)) {
        // Row/Text/Canvas 按 好感色阶 画关系表 —— 一次写好，终身复用
    }
}
判定逻辑：TagRegistry 注册时声明 native = true，分段器遇到该标签走 Compose 组件、其余走 WebView。
最终架构一句话：regex_scripts 直读引擎（通用、零成本接新卡）+ WebView 池（像素级还原）+ TagRegistry 原生快轨（高频标签性能兜底）——三层叠加，就是 APK 里对这类卡渲染的“完美”通用解。
