## 四、测试中发现并修复的 2 个真实 Bug

### BUG-A：JS 桥缺 `mkdir`，B1 分片写全部失败
- **现象**：`writeText .jskzx_cache/02.json` → `目标目录不可用(未授权)`（首轮构建）
- **根因**：`scheduleCacheFlush` 调用 `window.electronAPI.mkdir?.(CACHE_DIR)`，但 `electronAPI` 桥对象**未暴露 mkdir**（原生 `LibraryFs.mkdir` 存在，JS 侧只有 `createGroupFolder` 间接使用）→ 可选链静默跳过 → 分片目录从未创建
- **修复**：`android.js` 桥对象新增 `mkdir(path)`（toRelativePath + `LibraryFs.mkdir`）
- **复测**：`.jskzx_cache/` 目录创建成功，16 分片全部写入 ✅

### BUG-B：`SqliteMetaPlugin.init` 用了 `execSQL("SELECT 1")` → P2 DB restore 永久回退
- **现象**：`meta init failed: unknown error (code 0 SQLITE_OK): Queries can be performed using SQLiteDatabase query or rawQuery methods only`
- **根因**：`SQLiteDatabase.execSQL()` 禁止执行 SELECT 语句；init 探活抛异常 → `metaInit()` 返回 false → `restoreFromMetaDb` 回退 JSON 分片路径（DB 数据虽已写入但读不出来）
- **修复**：`try (Cursor c = db().rawQuery("SELECT 1", null)) { c.moveToFirst(); }`
- **复测**：`init` + `queryCards` 均成功 → 二次启动走 DB restore → **907ms** ✅

> 这两个 bug 都是"只在真机/模拟器运行才暴露"的集成缺陷（单测与构建均无法发现），正是本次实测的价值所在。

## 六、结论

**通过（P0 + P1 + P2 核心路径全部验证）**：

1. **A1 批量枚举是本轮最大收益**：单文件枚举成本从 28.6ms 降至 0.88ms（**约 32 倍**），5411 文件 4.8 秒完成。两万卡按此比例预计 ~18 秒（原推算 8-10 分钟）。
2. **A2/B1/P2 全部落地生效**：分块拉取、16 分片增量缓存、SQLite 元数据库（4988 行 + DB restore）。
3. **二次启动 907ms 秒开**（DB restore 路径），达到 <3s 目标。
4. **无功能回归**：授权、冷扫描、列表、分组、搜索、详情、增量 reconcile 全部正常。
5. **发现并修复 2 个集成 bug**（mkdir 桥缺失 / SQLite init execSQL 误用）——均已在模拟器复测通过。

**待办（真机）**：E2 二次查重秒级、两万卡全量规模、异常路径、分片写盘优化（85.5s → 目标 <20s）。
