## 一、真机发现并当轮修复的缺陷

### 真机 BUG-1（P1 阻断）：切回 SAF 后端时 `root_path` 未清除，换目录无效

**现象**：路径模式下点「重新选择库目录」→ 选另一个目录 → 授权成功后，卡库内容**仍来自旧的路径目录**，
`libraryInfo()` 仍返回 `backend:"path"`。实测 prefs 出现三个键并存：

```xml
<map>
    <string name="root_path">/storage/emulated/0/Download/BigScan</string>   <!-- 未被清除 -->
    <boolean name="root_persisted" value="true" />
    <string name="root_uri">content://…tree/primary%3ADownload%2FBigScan</string>
</map>
```

**根因**：`isPathBackend()` 与 `rootFile()` 都是**路径后端优先**，而 `setRootUri(Uri, boolean)`
只写了 `root_uri`/`root_persisted`，漏了 `remove(KEY_ROOT_PATH)`
（执行版 §2.1 明确要求此行，实现时遗漏）。

**修复**（`LibraryFsPlugin.java` `setRootUri`）：

```java
} else {
    // 切回 SAF 后端必须清掉 root_path:isPathBackend() 优先判定路径后端,
    // 残留会让「重新选择库目录」后仍然读旧路径(真机实测:root_path 未清 → 换目录无效)
    ed.putString(KEY_ROOT_URI, uri.toString())
            .putBoolean(KEY_ROOT_PERSISTED, persisted)
            .remove(KEY_ROOT_PATH);
}
```

`uri == null` 分支同样补 `.remove(KEY_ROOT_PATH)`。

**修复后真机复验**（同一操作路径）：

```xml
<map>
    <boolean name="root_persisted" value="true" />
    <string name="root_uri">content://com.android.externalstorage.documents/tree/primary%3ADownload%2FTestCards</string>
</map>
```

日志从 `relIndex(path) built: 300 entries` 变为 `relIndex built: 4 files, 0 dirs (A1 batch cursor) · dirs=1 rows=6 fails=0` ✓

## 七、追加：次要问题 A / B 的修复与真机复验（同日 14:18–14:22）
