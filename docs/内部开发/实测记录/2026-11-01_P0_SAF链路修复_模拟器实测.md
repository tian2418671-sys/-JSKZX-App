## 一、改动范围（P0，含终审 C.2 四项修正）

| # | 位置 | 改动 | 对应门禁 |
| --- | --- | --- | --- |
| 1 | `LibraryFsPlugin.putInitialDownloadsUri()` | `EXTRA_INITIAL_URI` 由 MediaStore 媒体 URI 改为 `DocumentsProvider` document URI，并用 `PackageManager.resolveContentProvider` 探测（未授权前不可 `query`） | 方案 2.1 / 核验 §1-1 |
| 2 | `tryPersistUriPermission()` | 按 `data.getFlags()` 掩码持久化 + 只读降级；结果写入 `KEY_ROOT_PERSISTED` 并回传 `persisted/persistedFlags/persistWarning` | 方案 2.2 |
| 3 | `setRootUri(uri, persisted)` + `clearRelIndex()` | 双后端互斥字段落地；索引清理改投递到 `SCAN_EXEC`，`docInfoCache` 改 `ConcurrentHashMap` | **终审 C.2-1 / C.2-4** |
| 4 | `queryChildrenSettled()` | resolver 级 `ContentObserver` 等待 `EXTRA_LOADING`，单目录 1500ms + 单次扫描 4000ms 总预算 | 方案 2.4 / **C.3-2** |
| 5 | `buildRelIndex()` | 子项查询接入 `queryChildrenSettled`；保留显式投影、失败降级与统计口径 | 方案 2.3 |
| 6 | `scanFolderResult()` | 整段遍历移入 `SCAN_EXEC`，改 Cursor 遍历，**保留 `success/treeUri/files/title` 契约**，进度事件字段固定为 `count/found` 并限流 250ms | 方案 2.5 / **C.2-5** |
| 7 | `walkDir()` / `scanWbTree()` | 接入 Cursor 枚举（`walkDir` 保留 `listFiles()` 兜底为 `walkDirLegacy`） | 方案 2.6 |
| 8 | `pickPushFolderResult()` | 返回 `title` + `name` 双字段（前端读 `title`） | **C.2-2** |
| 9 | `libraryInfo()` | 返回 `backend / persisted / reason`；`granted` 改为 `exists && canRead` | 方案 2.5 |
| 10 | `js/bridge/android.js` | `libraryInfo` 透传新字段；`selectFolder` 恢复 `rescanLibrary` 并带 `persisted/persistWarning` | 方案 4.1 |
| 11 | `SettingsView.vue` / `CardLibraryView.vue` | `persistWarning` 以 toast 呈现，不再"假报成功" | 方案 4.3 |

> 传输层删除了已无引用的私有方法 `relPathWithin()`（Cursor 遍历后不再需要回溯父链）。

## 六、未覆盖项（需真机或异常 provider）

| 项 | 原因 | 复验方式 |
| --- | --- | --- |
| `EXTRA_LOADING` 等待生效 | AOSP 本地 provider 不会返回半空 Cursor（`rows=849, fails=0` 说明未触发等待） | 真机（OPPO/云盘 provider）观察 `Perf: EXTRA_LOADING` 日志 |
| 受限路径归因文案 | 模拟器上无法构造可选的 `Android/data` 目录 | OPPO 真机选 `Android` 目录，应出现"独立卡库 + 导入/推送"提示 |
| `persistWarning` 分支 | 模拟器 provider 一定给持久化授权 | 三方文件管理器的自定义 DocumentsProvider |
| 3000+ 文件磁盘扫描 | 夹具仅 4 个文件 | 真机选大目录观察无 ANR 与进度刷新 |
