# 自定义背景图功能（设置页）

> 日期：2026-09-22 · 分支：main-v1.10（v1.10.29 基线）
> 需求：设置页新增「自定义背景」，用户可选一张图片作为全局背景并调节显示强度
> 结论前置：**已实现并模拟器实测通过**（选图 → 立即生效 → 杀进程重启自动恢复 → 可见度滑条可拖拽）

---

## 一、功能设计

| 要素 | 方案 |
|---|---|
| 入口 | 设置页「外观」下方新增「自定义背景」分组：背景图（含预览缩略图）/ 背景可见度滑条 / 移除背景图 |
| 选图 | 复用原生 `LibraryFsPlugin.pickImage`（系统照片选择器，返回 base64），浏览器预览环境回落 `<input type=file>` |
| 存储 | 图片本体存 **IndexedDB**（`jskzx-bg-v1` → `custom-background`，Blob）；可见度存 localStorage（`jsmobile-bg-visibility`，默认 80） |
| 压缩 | 选图后 canvas 处理：最长边 ≤2560px、WebP q0.85 优先（保留透明）、失败回退 JPEG；**已足够小（尺寸达标且 ≤3MB）则原样存储免二次编码** |
| 显示 | `.mobile-shell` 多层背景：第 1 层主题色遮罩（`rgba(<主题底色>, 遮罩浓度)`）+ 第 2 层图片（cover）；内部滚动发生在 `view-body`，背景天然固定 |
| 可读性 | 遮罩浓度 = `1 − 可见度`（20%→0.8 重遮融入主题底色；100%→0 完全清晰），文字始终在卡片（不透明/主题色）之上，不受图片干扰 |

### 关键取舍

- **不用 blur 做"毛玻璃"**：全屏模糊是移动 WebView 的字体模糊/性能元凶（P0a 已全主题禁用），背景融合改用"主题色半透明遮罩"实现，零滤波成本。
- **不用原生私有目录 + convertFileSrc**：IndexedDB 是标准 Web API，零原生改动、图片解码与显示全程在 WebView 内闭环；持久化能力与文件系统等价（随应用数据保存/清除）。
- **遮罩色跟随主题**：`theme.js` 将主题底色收敛为单一数据源 `THEME_BG_RGB`（body 背景与遮罩色共用），切换主题时照片自动与底色融合（深色主题压暗、浅色主题提亮）。

## 三、模拟器实测（JSKZX_Test / Android 35 / 1080x2400 / dpr 2.625）

| 项 | 结果 |
|---|---|
| 选图 | 照片选择器选中 1080x2400 JPEG（222,887B）→ 尺寸达标 ≤3MB，原样存储；秒级应用，无需重启 |
| 应用效果 | 设置页与卡片库均即时生效；后台 `--stc-bg-image=blob:...`、`--stc-bg-mask-alpha=0.2`（80% 可见度） |
| 可见度滑条 | 拖拽 80%→35%（遮罩精确换算 0.65；localStorage 同步 35）；拖回 80% 正常 |
| 持久化 | `am force-stop` 冷启动后背景自动恢复（IDB 读取 → blob URL → CSS 变量） |
| 回归 | `npm test` 147/147 通过；构建成功 |

**自动化技巧**：`adb shell input swipe/tap` 无法驱动 Vant 滑条（WebView 合成器层干扰，历史同类现象），改用 CDP `Input.dispatchTouchEvent` 连续序列（touchStart → 14×touchMove → touchEnd）拖拽成功；脚本 `cdp-swipe.js`（工作区外 `E:\jskzx-shots\`，可复用）。

## 四、已知边界与后续可选

1. 选图上限沿用原生 `pickImage` 的 20MB；超大原图（>50MP）解码可能吃紧，压缩失败时兜底存原图（try/catch 已包）。
2. 「移除背景图」路径未在本次实测中执行（避免清掉演示数据）：实现为 IDB 删除 + 变量清除，逻辑与选图共用同一应用通道。
3. 可选增强（未做，待需求）：自定义遮罩浓度上限（当前固定 20%~100%）、按主题分别记忆可见度、多图管理。
