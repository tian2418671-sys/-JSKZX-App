# 主题系统升级方案（v2 评审稿）

> 版本：v2 修订 · 2026-09-17 · 基于 v1.10.28（aad6573）
> 触发：用户反馈"主题功能只能改颜色 + 改变颜色后字体模糊不清"
> 修订依据：v1 方案评审意见（技术错误修正 / 层级分离补入 / 内核排查前置 / 旧变量单向引用）
> 状态：**待 v2 评审，未改任何代码**

---

## 一、现状问题诊断

### 1.1 "字体模糊"：两层叠加问题

**第一层：全屏模糊装饰层（性能 + 对比度）**
`theme-mobile-app.css:466-474` 定义了全屏装饰层：
```css
html .mobile-shell::before {
    content: '';
    position: absolute;
    inset: 0;           /* 全屏覆盖 */
    opacity: var(--stc-deco-opacity, 0);  /* 0.03~0.15 */
    filter: blur(var(--stc-deco-blur, 0)); /* 40~100px */
    z-index: 0;
}
```
各主题 blur/opacity 值：

| 主题 | blur | opacity | 视觉效果 |
|---|---|---|---|
| 未来 scanline | 80px | 0.10 | 霓虹扫描线 |
| 赛博朋克 glitch | 100px | 0.15 | **最重**（100px blur + 15% 不透明） |
| 汉风 seal | 40px | 0.05 | 半透明模糊 |
| 古风 scroll | 60px | 0.03 | 毛玻璃纹理 |
| 水墨 ink | 60px | 0.04 | 墨色模糊纹理 |

文字模糊感知来源：`inset:0` + `z-index:0` 使全屏伪元素绘制在**所有非定位内容之上**，半透明模糊层叠加在前景文字上 → 对比度骤降 → "字体模糊"。

**第二层：主题字体本身的清晰度（需排除）**：楷体/宋体是系统字体不存在 swap 问题，但缺字设备的 fallback 链顺序会影响渲染；部分 Web 字体（如未来主题的等宽字体）的 swap 可能导致 FOUT 模糊。P0 需做**主题 × 字体交叉截图**区分两个责任源。

### 1.2 "只能改颜色"——扁平色值体系，非语义色板

当前每个主题定义约 80-100 个扁平色值（具体色值 + 圆角 + 字体）。组件直接引用具体变量（如 `--dark-bg`/`--dark-text`），而非语义（`--color-primary`/`--color-surface`）。

后果：
- 换主题 = 覆盖 100 个变量（笨重）
- 无法做透明度/饱和度微调
- 组件不跟随 `color-scheme`（滚动条/input 控件不跟随暗色）
- 无组件迁移规则，新代码继续硬编码

## 二、WebView 内核排查（前置任务）

v1 方案未做的一项关键排查：

| 特性 | 最低 Chromium | 风险 |
|---|---|---|
| OKLCH 颜色 | 111+ | 旧内核下变量声明**静默失效**，主题色直接丢失 |
| View Transitions | 111+ | API 不存在，`startViewTransition` 报错 |
| relative color syntax（P2 需要） | 119+ | 同上 |
| `@supports (color: oklch(...))` | 111+ | 可用于渐进增强 |

- 标准 Android System WebView（2026 主流版本远超 111），风险低
- **国内 App 可能使用腾讯 X5/TBS 内核或旧版 Chromium（停留在 8x）**——需前置排查
- **前置任务**：线上 UA + `@supports` 特性检测摸底内核分布；OKLCH 需加 hex 兜底：
```css
[data-theme="dark"] { --color-primary: #6d5dfc; } /* hex 兜底 */
@supports (color: oklch(50% 0.1 200)) {
    [data-theme="dark"] { --color-primary: oklch(58% 0.233 277.117); }
}
```

## 三、升级方案

### 3.1 装饰层修复（P0a + P0b 两步）

**P0a（层级分离 + 禁用 blur，立竿见影）**

```css
/* 第一步：层级分离（一行恢复对比度） */
.mobile-shell > .app-content {
    position: relative;
    z-index: 1;  /* 文字永远在装饰层之上 */
}
```
这一行的效果：即使装饰层继续用 blur，前景文字也不再被半透明层覆盖 → 对比度恢复。先在真机验证此行是否立竿见影，作为根因确认。

```css
/* 第二步：全局禁用 blur（P0a 保底） */
html .mobile-shell::before {
    filter: none; /* 去掉所有 blur，恢复为无滤镜状态 */
    /* 保留 opacity，让主题纹理仍可见（但不再模糊） */
}
```
禁用 blur 后装饰层退化为半透明色块（可接受的降级效果）。这是"字体模糊"的立即修复方案。

**P0b（装饰层渐变重写，~1 天）**

用渐变/阴影替代 blur，实现"柔和纹理"且零性能损失：

```css
/* 赛博朋克：霓虹光斑（radial-gradient 天然柔和，零滤波） */
[data-theme="cyberpunk"] .mobile-shell::before {
    background:
        radial-gradient(600px 400px at 20% 0%, var(--deco-color-1, #ff00ff) 0%, transparent 70%),
        radial-gradient(500px 350px at 85% 100%, var(--deco-color-2, #00ffff) 0%, transparent 70%);
    opacity: 0.12;
}

/* 未来主题：扫描线纹理（细密重复线自带柔和观感） */
[data-theme="future"] .mobile-shell::before {
    background: repeating-linear-gradient(
        to bottom,
        transparent 0 3px,
        rgba(255,255,255, 0.03) 3px 4px
    );
    opacity: 0.8;
}

/* 水墨/古风/汉风：纸张纹理（纯 CSS gradient 实现，无 blur） */
[data-theme="ink"] .mobile-shell::before,
[data-theme="ancient"] .mobile-shell::before,
[data-theme="han"] .mobile-shell::before {
    background:
        radial-gradient(ellipse at 30% 20%, rgba(var(--deco-r,120),var(--deco-g,100),var(--deco-b,80),0.08) 0%, transparent 60%),
        radial-gradient(ellipse at 70% 80%, rgba(var(--deco-r,100),var(--deco-g,80),var(--deco-b,60),0.06) 0%, transparent 50%);
    opacity: 0.9;
    filter: none;
}
```
注意：即使去掉 blur，全屏 0.15 不透明层仍会降对比度（赛博朋克主题最重），渐变重写时应同步把不透明度上限压低（≤0.12），或将全屏纹理改为局部光斑。

**P0 执行顺序**：层级分离验证（0.5天）→ 确认根因后 → 8 主题渐变重写 + 设计确认（1天）。总计 P0 = 1.5 天。

### 3.2 语义色板重构（P1，先 2 主题试点 → 铺开）

**旧变量处理原则：旧变量 = 新语义变量的别名（单向引用），非双套维护**：

```css
/* 暗色主题示例（语义变量是唯一数据源） */
[data-theme="dark"] {
    color-scheme: dark;                    /* 原生控件跟随 */
    --color-base-100: #17181c;            /* 背景底层 */
    --color-base-200: #1f2226;            /* 背景次层 */
    --color-base-300: #272b30;            /* 背景深层 */
    --color-base-content: #fafafa;        /* 文字色 */
    --color-primary: #6d5dfc;             /* 主色 */
    --color-primary-content: #ffffff;     /* 主色上的文字 */
    --color-secondary: #9089fc;           /* 次品牌色（非 UI 组件色，仅语义） */
    --color-accent: #57c4e5;              /* 强调色 */
    --color-success: #43e97b;             /* 成功色 */
    --color-error: #e74c3c;               /* 错误色 */
    --color-warning: #f0932b;             /* 警告色 */
    --color-info: #4da6ff;               /* 信息色 */
    --color-border: #374151;              /* 边框/分割线 */
    --color-muted: #9ca3af;              /* 次要文字/占位符 */
    --radius-box: 10px;                  /* 卡片/容器圆角 */
    --radius-field: 8px;                 /* 输入框圆角 */
    /* 旧变量 = 别名，旧组件零改动自动跟随 */
    --dark-bg: var(--color-base-100);
    --dark-card-bg: var(--color-base-200);
    --dark-deep-bg: var(--color-base-300);
    --dark-text: var(--color-base-content);
    --dark-accent: var(--color-primary);
    --dark-tab: var(--color-base-200);   /* tab 未选中态归 base-200/neutral，非 secondary */
}
```

**P1 实施策略**：先选 1 暗（dark）+ 1 浅（light）试点打通语义变量链路，确认无循环引用后铺开 8 主题。旧变量别名 = 新语义变量的引用（**单向引用，非双份维护**），迁移完成后删除旧变量只需删别名行。禁止新代码直接引用旧变量（CI 规则，见第五节）。

**语义变量表补全**（评审补充）：新增 `--color-border`（边框/分割线，主题化高频项）、`--color-muted`（次要文字/占位符）；`secondary` 定位为次品牌色（非 UI 组件色）；`base-100/200/300` 统一为背景层级，删除冗余的 `surface/card` 概念；每色配对 `X-content`（primary/secondary/accent/success/error/warning/info 均配对）。

**OKLCH 兜底**：暗色主题 OKLCH 值需加 hex 兜底（评审第 3 条），`@supports` 条件覆盖：
```css
[data-theme="dark"] { --color-primary: #6d5dfc; } /* hex 兜底，旧内核安全 */
@supports (color: oklch(50% 0.1 200)) {
    [data-theme="dark"] { --color-primary: oklch(58% 0.233 277.117); }
}
```

### 3.3 color-scheme 逐主题声明（而非只给暗色加 dark）

```css
[data-theme="dark"],
[data-theme="slate"],
[data-theme="cyberpunk"],
[data-theme="future"] { color-scheme: dark; }

[data-theme="light"],
[data-theme="ancient"],
[data-theme="han"],
[data-theme="ink"] { color-scheme: light; }
```
确保浅色主题（古风/汉风/水墨）不被全局 `color-scheme: dark` 错误影响。

### 3.4 View Transitions 切换动画（P1 + 降级路径）

```js
function applyThemeSafe(nextTheme) {
    if (document.startViewTransition
        && !matchMedia('(prefers-reduced-motion: reduce)').matches
        && currentTheme() !== nextTheme) {
        document.startViewTransition(() => {
            applyTheme(nextTheme); // 核心主题切换逻辑（data-theme + 变量 + class）
        });
    } else {
        applyTheme(nextTheme); // 降级：瞬时切换，功能不受损
    }
}
```
- 前提：`document.startViewTransition` 存在且用户未开启减少动画
- 降级：API 不存在或用户设置 reduce-motion → 直接瞬时切换（兼容性保证）
- 切换瞬间禁用现有 CSS transition（避免双重动画）
- 字体切换使用 `font-display: swap`（Web 字体场景），避免快照闪烁

### 3.5 Material You 动态取色（P2，结论明确）

调研结论：**WebView 沙箱拿不到系统壁纸，Material You 式取色在本项目不可行**。可演进方向：用户手动选图取色，或用 OKLCH 的 `relative color syntax`（Chromium 119+）从主色 tone 生成 secondary/tertiary。P2 可做"主题颜色微调滑块"（调 C/L 分量），实现 OKLCH 的设计优势。

### 3.6 字体切换优化 + 排除低对比度误诊

- 字体切换只改 `--theme-font`，不改 `font-size`（当前实现正确）
- 各主题字体列表末尾加通用 fallback（`sans-serif`/`serif`/`monospace`）防缺失设备渲染
- Web 字体的 `font-display: swap` 会带来 FOUT 布局抖动，需 `size-adjust`/`ascent-override` 缓解
- **P0 验收需要做"主题 × 字体交叉截图"**：区分"低对比度发糊"（装饰层问题，P0a 解决）与"楷体小字本身发虚"（字体问题，P0b 字体列表优化）两个责任源

## 五、验收标准

| 项 | 标准（可执行） |
|---|---|
| 字体清晰度 | 所有主题下正文对比度 ≥ 4.5:1（WCAG AA，大字 ≥ 3:1）；**用 WebAIM 对比度计算器验证，或 DevTools 颜色拾取计算** |
| 主题切换流畅 | View Transition 成功切换 / 降级时瞬时切换（无卡顿）；DevTools Performance 录制：**长任务 < 200ms** |
| 原生控件跟随 | 暗色主题下 `color-scheme: dark` 生效 → WebView 滚动条/input 背景自动变暗 |
| 8 主题一致性 | 每主题有完整语义变量（primary/base/content/error/...），无硬编码旧变量直接引用；**新增代码 CI 规则检查禁止引用旧扁平变量**（见下方） |
| 旧主题兼容 | 旧组件引用旧变量仍正常（别名单向引用，无漂移）；迁移后删除别名无需改组件 |
| 字体交叉 | 8 主题 × 字体 fallback 链：主题字体缺失时自动 fallback 到 sans-serif/serif/monospace，不渲染空白 |
| 渐变装饰 | 装饰层渐变视觉与原 blur 近似（设计确认）；opacity ≤ 0.12（确保对比度 ≥ 4.5:1） |
| CI 规则 | 新增代码若引用旧变量（`--dark-`/`--light-` 前缀非别名行）→ lint 失败（禁止新增对旧变量的直接引用） |

## 六、CI 规则（"无硬编码遗漏"持续保障）

在 ESLint/Vant 项目中新增自定义规则或 git hook：
```bash
# 简单实现：grep 新变更代码（git diff HEAD）是否有直接引用旧变量
git diff HEAD -- '*.css' '*.vue' | grep -E '\-\-(dark|light)-[a-z]+-(?!:)' && \
    echo "❌ 新增代码禁止直接引用旧主题变量（请用 --color-* 语义变量）" && exit 1
```
此规则只检查**新增行**（git diff），不扫描存量（存量迁移是 P1 工作项），避免误伤。

## 七、风险与开放问题

| 风险 | 缓解 |
|---|---|
| 渐变装饰层在部分低端 Android WebView 渲染慢 | 测试覆盖低端机；渐变复杂度控制（仅 2-3 个 radial-gradient / repeating-linear-gradient，无 blur） |
| OKLCH 在旧内核静默失效（主题色丢失） | hex 兜底 + @supports 条件（前置排查确认）；旧内核走 hex，不报错 |
| View Transitions 在旧内核 API 不存在 | 降级瞬时切换（代码已有，不依赖 API） |
| font-display: swap 导致 FOUT 布局抖动 | size-adjust / ascent-override 缓解；渐进式字体预加载（P2） |
| 语义变量迁移遗漏 | CI 规则检查新增行；P1 先 2 主题试点再铺开（降低一次性变更风险） |
| 赛博朋克渐变设计确认 | P0b 需设计介入确认渐变效果；降级保留 blur 方案作为 fallback |

## 八、结论

v2 修正后：删除错误的 backdrop-filter 方案 A；补入层级分离（一行解决对比度问题，P0 第一步）；内核排查前置；旧变量改为单向引用；color-scheme 逐主题声明；View Transitions 加降级路径；P0 拆为 P0a（0.5天 层级+禁blur）+ P0b（1天 渐变重写），工作量更真实；验收标准量化为 WCAG AA + DevTools 性能指标；新增 CI 规则持续保障变量迁移。

**修正后方案可进入实施。**
