# 扩展功能验证计划（2026-09-13）

基于经验教训，系统扫描其他核心链路的运行时脆弱点。

---

## 测试清单（优先级顺序）

### P0：关键数据完整性（高风险）

#### 0.1 卡片导入与去重
**场景**：连续导入同一张卡 3 次，观察最终卡片列表

**预期**：
- 列表中只出现 1 张卡（去重成功）
- 或明确提示「已导入」（不重复添加）

**检查点**：
- [ ] 导入后卡片列表数量是否正确
- [ ] 快速连续导入是否有竞态（多份卡片或混淆）
- [ ] 导入中途切 tab 是否会导入失败或混乱

**风险等级**：🔴 严重（数据一致性问题）

---

#### 0.2 世界书编辑保存
**场景**：进入某卡片的世界书标签，新增一条条目，修改内容，保存

**预期**：
- 重新打开该卡片，世界书条目仍在且内容不变
- 删除该条目后保存，重新打开时条目确实消失

**检查点**：
- [ ] 新增条目是否真的保存到卡片文件
- [ ] 编辑条目内容是否真的更新
- [ ] 删除条目是否真的落盘（不是仅 UI 删除）

**风险等级**：🔴 严重（数据丢失风险）

---

#### 0.3 预设条目开关有效性
**场景**：打开某预设，找一个 prompt 条目（如「scenario」），关闭它，保存

**预期**：
- 后续该条目对生成不再生效（在测卡时不包含该条目内容）

**检查点**：
- [ ] 开关状态是否被正确保存
- [ ] 重新打开预设时开关状态是否恢复
- [ ] 测卡时是否真正排除已关闭的条目

**风险等级**：🟡 高（功能有效性问题）

---

### P1：用户交互稳定性（中风险）

#### 1.1 快速搜索切 tab 后的幽灵过滤
**场景**：搜索「alice」，在 300ms 防抖完成前快速切换到另一个 tab，再切回来

**预期**：
- 列表显示全量卡片（搜索被彻底清除）
- 搜索框已清空

**检查点**：
- [ ] 返回后是否只显示搜索结果而不是全量（幽灵过滤）
- [ ] 搜索框是否被复位
- [ ] 是否有多余的搜索状态残留

**风险等级**：🟡 高（BUG-13 已修，需验证）

---

#### 1.2 快速刷新后列表混乱
**场景**：列表加载中（显示 loading），快速点击刷新按钮 3 次

**预期**：
- 列表不翻倍、不混乱
- 刷新完成后卡片数量正确

**检查点**：
- [ ] 最终列表卡片数是否正确（无翻倍）
- [ ] 卡片顺序是否混乱
- [ ] 是否有重复卡片出现

**风险等级**：🟡 高（BUG-12 已修，需验证）

---

#### 1.3 导入中途中断（权限撤销/返回）
**场景**：选择 SAF 目录开始导入，在导入进度中按返回键

**预期**：
- 导入中止或显示「已中止」
- 列表状态回到导入前的状态（无部分导入的混淆）

**检查点**：
- [ ] 中止后是否有错误提示
- [ ] 列表是否有部分卡片遗留（脏数据）
- [ ] 是否能再次重新导入

**风险等级**：🟡 高（中断处理问题）

---

### P2：数据一致性与性能（低风险，但仍需验证）

#### 2.1 缓存和二次启动
**场景**：

1. 启动应用，扫描卡库，显示 N 张卡
2. 完全杀死应用（后台清理）
3. 重新启动应用

**预期**：
- 二次启动几乎瞬间显示卡库（缓存生效）
- 卡片数量与顺序与第一次相同

**检查点**：
- [ ] 缓存文件是否存在（`~/.jskzx_cache.json`）
- [ ] 二次启动是否真的秒开（<2s）
- [ ] 缓存内容是否与实际文件同步

**风险等级**：🟢 低（缓存逻辑已成熟）

---

#### 2.2 快照删除功能
**场景**：编辑卡片多次（存储多个快照），进入快照面板，删除某个快照

**预期**：
- 快照确实被删除
- 快照列表更新
- 再次打开卡片时不出现已删除的快照

**检查点**：
- [ ] 删除是否真的成功（不再提示「非法路径」等）
- [ ] 快照列表是否正确刷新
- [ ] 已删除的快照是否不会再出现

**风险等级**：🟢 低（教训 2 已修）

---

#### 2.3 世界书条目大量导入
**场景**：导入一个有 200+ 条目的世界书

**预期**：
- 条目列表正确加载
- 滚动流畅（无明显卡顿）
- 搜索条目正常响应

**检查点**：
- [ ] 条目总数是否正确
- [ ] 条目列表是否能快速滚动（无明显卡顿）
- [ ] 搜索条目性能是否可接受

**风险等级**：🟢 低（列表渲染已优化）

## 自动化验证脚本模板

### 脚本 1：导入去重验证
```bash
# scripts/test-dedup-import.mjs
# 1. 启动应用，选择 SAF 目录
# 2. 获取导入前卡片数 N
# 3. 导入同一张卡 3 次，检查是否只增加 1 张卡（或提示重复）
# 4. 最终卡片数应为 N+1（或 N，如果系统拒绝重复导入）
```

### 脚本 2：搜索幽灵状态验证
```bash
# scripts/test-search-ghost.mjs
# 1. 启动应用，进入卡库
# 2. 输入搜索词「test」
# 3. 在 100ms 时切到「设置」tab
# 4. 在 350ms 时切回卡库
# 5. 检查：列表应为全量，搜索框应清空
```

### 脚本 3：快速刷新竞态验证
```bash
# scripts/test-rapid-refresh.mjs
# 1. 启动应用，扫描到卡库（记录初始卡片数 N）
# 2. 快速点击刷新按钮 5 次
# 3. loading 完成后，检查最终卡片数是否仍为 N（无翻倍）
# 4. 随机抽样 5 张卡验证指纹一致性
```
