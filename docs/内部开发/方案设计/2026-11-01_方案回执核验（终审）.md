## 2. 编译级阻断（原样粘贴必然构建失败，共 4 条）

### 2.1 非法常量：`Intent.FLAG_Grant_PREFIX_URI_PERMISSION`

回执 `scanFolder()` 片段：

```java
intent.addFlags(Intent.FLAG_GRANT_READ_URI_PERMISSION
        | Intent.FLAG_GRANT_PERSISTABLE_URI_PERMISSION
        | Intent.FLAG_Grant_PREFIX_URI_PERMISSION);   // ← 常量不存在
```

**判定**：❌ 不成立。Android SDK 常量为 `FLAG_GRANT_PREFIX_URI_PERMISSION`（全大写 `GRANT`）。
且定向选择目录（`ACTION_OPEN_DOCUMENT_TREE`）由系统自行授予持久化权限，**这三个 flag 均非必要**。

**修正建议**：整段 `addFlags` 删除（保留 `putInitialDownloadsUri(intent)` 即可）。

### 2.2 未定义方法：`clearRelIndex()`

回执在 `pickFolderResult()` 与 `setLibraryRootPath()` 中调用：

```java
clearRelIndex();   // ← 本地无此方法
```

**判定**：❌ 不成立。本地索引清理是内联实现（`LibraryFsPlugin.java:156` 起 `buildRelIndex()` 内
`synchronized (relIndex) { relIndex.clear(); … }`，`:247` 设置 `relIndexReady`），没有此方法。

**修正建议**：新增私有方法

```java
/** 库根变更后必须失效索引,否则旧树的 relPath 会命中失效的 DocumentFile */
private void clearRelIndex() {
    synchronized (relIndex) { relIndex.clear(); }
    docInfoCache.clear();
    scanFilesList = new java.util.ArrayList<>();
    scanDirsList = new java.util.ArrayList<>();
    relIndexReady = false;
}
```

### 2.3 未定义方法：`scanTreeCursorRecursive(...)`

回执 `scanFolderResult()` 直接调用：

```java
scanTreeCursorRecursive(appCtx.getContentResolver(), treeUri, rootDocId, "", extFilter, files);
```

**判定**：❌ 不成立。回执全篇未给出该方法实现，且 `files` 内元素字段未定义。

**修正建议**：复用本地既有能力，不要引入新递归器——直接调用 `buildRelIndex()` 的成果
（`scanFilesList`），或按 §3.1 的返回契约自行遍历。最小改动写法：

```java
// 复用已建索引:遍历 scanFilesList(相对路径 + DocumentFile),按扩展名过滤
for (Object[] fr : scanFilesList) {
    String rel = (String) fr[0];
    String lower = rel.toLowerCase(Locale.ROOT);
    if (!(lower.endsWith(".png") || lower.endsWith(".webp"))) continue;
    JSObject o = new JSObject();
    o.put("path", rel);
    o.put("name", rel.contains("/") ? rel.substring(rel.lastIndexOf('/') + 1) : rel);
    CachedDocInfo info = docInfoCache.get(rel);
    o.put("size", info != null ? info.size : 0L);
    files.put(o);
}
```

### 2.4 Manifest 缺 `xmlns:tools`

回执声明：

```xml
<uses-permission android:name="android.permission.MANAGE_EXTERNAL_STORAGE"
    tools:ignore="ScopedStorage" />
```

**判定**：❌ 不成立。本地 `AndroidManifest.xml:2` 仅声明 `xmlns:android`，无 `xmlns:tools`

## 3. 契约级回归（能编译但打断既有功能，共 5 条）

### 3.1 `scanFolder` 返回结构被改 → **磁盘扫描功能整体失效**

回执新返回：

```java
JSObject ret = new JSObject();
ret.put("uri", treeUri.toString());
ret.put("files", files);        // 丢掉了 success / treeUri / title
call.resolve(ret);
```

本地消费方 `js/bridge/android.js:1362`：

```js
async scanTargetFolder() {
    const res = await LibraryFs.scanFolder({ ext: '.png', skipLarge: true });
    if (!res.success) return { files: [], error: res.message || '扫描失败' };   // ← res.success 缺失 → 恒判失败
    const files = (res.files || []).map((o) => ({ path: o.path, name: o.name, size: o.size || 0 }));
    if (res.treeUri) this._scanTreeUri = res.treeUri;                            // ← 导入依赖 treeUri
    if (res.title) this._scanTitle = res.title;
    return { files, treeUri: res.treeUri, title: res.title, error: undefined };
}
```

**判定**：❌ 不成立（阻断）。`res.success` 恒 `undefined` → 磁盘扫描 100% 报"扫描失败"；
`treeUri` 缺失还会使 `importScanned({ treeUri, scanPaths })` 直接返回「缺少扫描结果」。

**修正建议**：保持既有返回字段不变，只新增诊断字段。

```java
JSObject ret = new JSObject();
ret.put("success", true);
ret.put("treeUri", treeUri.toString());          // 必须保留
ret.put("engineUri", treeUri.toString());        // 回执原字段保留为别名,避免二次改前端
ret.put("files", files);                         // 元素必须含 path/name/size
ret.put("title", root != null ? root.getName() : "");
call.resolve(ret);
```

同时保留 `notifyListeners("scanProgress", …)` 心跳（回执片段把它一并删除了，
而 `DiskScanView.vue` 的进度文案依赖该事件）。

### 3.2 `selectFolder()` 改成 `return res` → **授权后库不加载 + 误报"未找到角色卡"**

回执（`js/bridge/android.js`）：

本地消费方：

回执为原生 `libraryInfo` 增加 `backend` / `reason`，但未同步 `js/bridge/android.js:366`：

## 4. 技术机制需修正（可编译但效果不达预期，共 6 条）

### 4.1 `c.registerContentObserver(observer)` 监听不到 provider 异步完成

回执：

```java
c.registerContentObserver(observer);            // Cursor 级
Bundle recheck = c.getExtras();
if (recheck == null || !recheck.getBoolean(DocumentsContract.EXTRA_LOADING, false)) latch.countDown();
```

**问题 1**：Cursor 级 observer 依赖 provider 在 Cursor 上设置了 `notificationUri`；未设置时永不回调。
MaterialFiles 与本仓库 [两万卡方案 2.2](./两万卡卡库性能方案.md) 均采用 **resolver 级**注册。

**问题 2**："注册后复查 `extras`"是**死代码**——同一 Cursor 实例的 `getExtras()` 是创建时快照，
不会随 provider 补行而刷新，因此该判断恒为旧值。

**修正代码**：

```java
private android.database.Cursor queryChildrenSettled(Uri childrenUri, long timeoutMs) {
    final android.content.ContentResolver cr = getContext().getContentResolver();
    android.database.Cursor c = cr.query(childrenUri, DOC_CHILD_PROJECTION, null, null, null);
    if (c == null) return null;
    boolean loading = false;
    try {
        android.os.Bundle extras = c.getExtras();
        loading = extras != null && extras.getBoolean(DocumentsContract.EXTRA_LOADING, false);
    } catch (Exception ignored) { }
    if (!loading) return c;

    final java.util.concurrent.CountDownLatch latch = new java.util.concurrent.CountDownLatch(1);
    android.database.ContentObserver obs = new android.database.ContentObserver(
            new android.os.Handler(android.os.Looper.getMainLooper())) {
        @Override public void onChange(boolean selfChange) { latch.countDown(); }
    };
    cr.registerContentObserver(childrenUri, true, obs);   // ← resolver 级,能收到 notifyChange
    try {
        latch.await(timeoutMs, java.util.concurrent.TimeUnit.MILLISECONDS);   // 超时兜底
    } catch (InterruptedException ignored) {
        Thread.currentThread().interrupt();
    } finally {
        try { cr.unregisterContentObserver(obs); } catch (Exception ignored) { }
        try { c.close(); } catch (Exception ignored) { }
    }
    return cr.query(childrenUri, DOC_CHILD_PROJECTION, null, null, null);    // 重开拿补全后的行
}
```

**注意**：该函数会阻塞当前线程，必须只在 `SCAN_EXEC` / `BATCH_EXEC` 等后台线程调用。

### 4.2 `requestLegacyExternalStorage="true"` 对本项目无效

`android/variables.gradle`：`targetSdkVersion = 36`。该属性仅在 `targetSdk ≤ 29` 时对 Android 10 生效，
项目 target 36 → **完全无效**。

**修正建议**：不要添加，避免后续维护者误判。

### 4.3 存储权限重复声明冲突

本地 `AndroidManifest.xml:53` 已存在：

```xml
<uses-permission android:name="android.permission.WRITE_EXTERNAL_STORAGE" android:maxSdkVersion="28" />
```

### 4.4 `buildRelIndex` 改造范围表述过时

回执称"在 `buildRelIndex()`、`scanWbTree()`、`scanFolderResult()` 中统一废弃 `DocumentFile.listFiles()`"。

**实际**：`buildRelIndex` 主干**早已是 Cursor 实现**（`:179` 显式投影 + 行缓存），`listFiles()` 仅存在于
降级分支（`:224`）。真正待改造的是：

| 位置 | 用途 |
| :--- | :--- |
| `:829` `walkDir()` | 子目录扫描（`scanStart` 带 rel 参数时走这条） |
| `:1929` `scanFolderResult()` | 磁盘扫描主遍历 |
| `:2342` `scanWbTree()` | 世界书/预设外部目录扫描 |
| `:1168` / `:1192` | 快照/回收站等辅助枚举 |

**修正建议**：改造清单以上表为准；`buildRelIndex` 的降级分支保留（provider 完全不支持 Cursor 时的最后兜底）。

### 4.6 验收用例 2 与接口定义不一致

**修正建议**：二选一——

② 用例改为「重新调用 `pickFolderResult` 前后的 `persisted` 值」，或直接校验「杀进程重启后 `granted == true`」。
