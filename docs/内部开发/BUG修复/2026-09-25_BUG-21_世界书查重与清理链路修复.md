## 二、深挖出的两个隐藏 BUG（清理链路）

### BUG-A：首次清理必失败（`trashByMove` 重试链够不着）

| 项 | 内容 |
|---|---|
| 现象 | 库根从未有 `.trash` 时点「清理其余版本」→ `已清理 0 个版本；1 个失败`（error=目标目录不可写）；旧清理成功只是「恰好 `.trash` 已存在」 |
| 根因（两层） | ① 原生 `move` 对「目标父目录不存在」是 **`call.reject`（抛异常）**，而 JS `trashByMove` 的降级重试（建目录后重试）写在 `resolve({success:false})` 分支 → 异常直接进 `catch`，重试**永远够不着**；② 旧代码用 `dest` 的字符串下标去切 `rel`（两串长度不同）→ 即便走到也会建出错误路径 |
| 修复 | 重写为 `trashOneByMove(fs, rel)`（导出注入式，可单测）：首次失败**无论 reject 或假值** → 按 `.trash → .trash/子目录` 逐级 mkdir（原生 mkdir 非递归、已存在幂等）→ 重试一次；新增单测 `test/trashRetry.test.mjs`（9 组：首次清理链/已存在一次成功/深子路径/resolve 假值/重试仍失败/空路径等） |

### BUG-B：relIndex 坏对象 → 跨目录移动「假失败」（根因最深）

| 项 | 内容 |
|---|---|
| 现象 | `.trash` 已存在后，移动**老文件**（如 adb 推入的世界书）仍 `移动失败`；但新建文件（writeText）正常；读文件一直正常 → "时好时坏" |
| 根因 | `buildRelIndex`（任何 scan 后触发）用 **`DocumentFile.fromSingleUri`** 包装文件对象；这种对象 **`getParentFile()` 为 null**、`findFile()` 不支持 → `move` 的 `doMove` 内 `src.getParentFile().getUri()` 恒 NPE 被 catch 吞掉 → 依赖 relIndex 命中的移动**全部假失败**。此前"能成功"的场景恰是：索引未建（慢查）/ 移动对象是 `.trash`（点开头目录不进索引）/ 刚 writeText（入索引的是正常对象） |
| 修复 | **写操作一律走慢查 `fileByRelPathSlow`**（逐段 `findFile` 拿 Tree 对象）：`move`（src+targetDir）、`mkdir`（parent）、`rename`（src）、`openFileInFolder`；移动成功后 `invalidateRelIndex(path)` 失效旧条目。**读路径保持快查**（URI 级操作对 single 对象全兼容）。写操作频率=用户交互级，慢查（2-4 次 query）成本可忽略 |

### BUG-C：清理「假成功」+ `trashFiles` 返回形式混乱

| 项 | 内容 |
|---|---|
| 现象 | 副本没清掉却提示「已清理 1 个版本；1 个失败」且组从 UI 消失（重开又出现）；世界书「删除」失败也显示成功 |
| 根因 | ① `trashFiles` 的 `success` 实际是**数组**（`[]` 也 truthy）→ 消费方判空逻辑全失效；② `failed[].path` 是**相对路径**而消费方用 `/library/` 完整路径匹配 → 失败项被判成功 |
| 修复 | `trashFiles` 统一返回 `{success:boolean(=count>0), count, okPaths[], failed[].path(均 /library/ 形式), error}`；`DedupeModal` 的 `doTrash` 改为返回 `okPaths|null`，`trashOne/trashRest` **成功哪些移除哪些、失败保留**（不再无差别删组） |

### 附带：主版本选择不稳定（UI 表现）

| 项 | 内容 |
|---|---|
| 现象 | 「完全一致」的副本若 mtime 更新，会被选为主版本 → 组名带 `_副本` 后缀、「清此版」指向原版 |
| 修复 | 排序改「本体优先」：文件名经 `stripCnReplicaTails` 无变化 = 本体 → 优先；再按 词条数 → mtime。重启后新加载顺序下主版本稳定=原版 |

## 四、经验沉淀

1. **「时好时坏」= 找差异变量**：索引命中 vs 慢查、对象来源（scan 索引 / writeText / 慢查）——对照实验（普通名 vs `---` 前缀、新建 vs 推入）快速收敛。
2. **被吞的 catch 是最贵的债**：`doMove` 的 `catch(Exception){return false}` 让三层故障（NPE/重试够不着/假成功）都伪装成同一句「移动失败」。
3. **relIndex 类风险约定**：任何「需要 Tree 语义」的写操作（getParentFile/findFile/renameTo）不得信任快查对象，一律慢查。
4. **验收=用户操作路径**：本轮所有断言按「复制副本→查重→清理→恢复」真实链路跑，不再只测「功能是否存在」。
