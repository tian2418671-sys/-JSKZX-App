# BUG-19 设置页最底部内容被 Tab 导航遮挡修复日志

> 日期：2026-09-22 · 分支：main-v1.10（v1.10.29 基线）
> 触发：用户反馈「设置页最下面被遮挡住了数据存储」，要求模拟器截图排查
> 结论前置：**根因 = 底部 Tab 导航为 `position: fixed`（高 51px）浮盖在内容之上，而各页面滚动容器底部留白不足（设置页仅 24px → 被遮 27px）。已统一四个页面的底部留白公式并模拟器实测修复。**

---

## 一、现象与定位过程

| 步骤 | 证据 |
|---|---|
| 复现 | 模拟器安装 v1.10.29 → 设置页滚动到底：`关于 → 数据存储` 仅露出标题上半部分，其路径内容不可见（归档截图 01） |
| 布局测量（CDP） | `van-tabbar`：`position: fixed`、`top=792 / bottom=842`（= 视口底），高 51px，**覆盖在内容之上** |
| 容器测量（CDP） | `.view-body`：`top=47 / bottom=842`（延伸到屏幕底）、`overflow-y: auto`；滚动到底时最后一项底边距屏底 = `padding-bottom` → **净可见间距 = padding-bottom − 51px** |
| 各页参数对照 | 设置页 `24px`（净 −27px，被遮）、卡片库 `12px`（净 −39px）、预设页 `20px`（净 −31px）、世界书页 `80px`（净 +29px，唯一正常） |

**机理**：mobile-shell 为 flex 纵向布局，但 `van-tabbar` 默认 `fixed` 定位（不占文档流），页面内容区（`flex:1`）实际延伸到屏幕底部、被导航栏浮盖。因此**每个带 Tab 导航的页面都必须自行在滚动容器底部预留 ≥ 导航高度的空白**，否则滚动到最底部时最后一项（或末行卡片）会被遮挡。

---

## 二、修复

统一四个页面滚动容器的底部留白公式（`tabbar 高 50px + 安全区 + 30px 视觉间距`）：

```
padding-bottom: calc(50px + env(safe-area-inset-bottom, 0px) + 30px);
```

| 页面 | 文件 | 修复前 | 修复后（safe-area=0 时） |
|---|---|---|---|
| 设置页 | `js/mobile/views/SettingsView.vue`（`.view-body`） | `24px` | `80px` |
| 卡片库 | `js/mobile/views/CardLibraryView.vue`（`.view-body`） | `12px` | `80px` |
| 预设页 | `js/mobile/views/PresetsView.vue`（`.pv-list`） | `20px` | `80px` |
| 世界书页 | `js/mobile/views/WorldbookView.vue`（`.view-body`） | `80px` 固定值 | `80px`（全面屏设备上 ≥ 80px，修正高安全区场景的潜在不足） |

- `env(safe-area-inset-bottom, 0px)` 保证手势条设备上随安全区增大同步加大留白；
- 修复后各页留白一律 ≥ 修复前，不存在「只增不减」以外的行为变化。

## 四、经验教训

1. **fixed 导航栏的「内容让位」必须逐页显式处理**——flex 布局里的 `mobile-tabbar { flex-shrink:0 }` 对 `fixed` 元素不生效，容易造成"以为它占位、实际它浮盖"的错觉。
2. **底部留白公式化**——`50px(tabbar) + env(safe-area-inset-bottom) + 视觉间距`，避免散落的魔法数字（本次统一 30px 间距）；新增带 Tab 导航的页面必须套用。
3. **验收手段**：滚动到底截图（人眼可辨）+ CDP 几何测量（`gap = tabbar.top − lastItem.bottom`，要求 > 0）双保险；后者可写成一键回归脚本。
