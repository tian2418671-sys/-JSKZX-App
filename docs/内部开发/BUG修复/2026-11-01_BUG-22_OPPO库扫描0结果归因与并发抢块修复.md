# BUG-22：OPPO 真机「授权库目录后扫描到 0 张」

> 日期：2026-11-01 · 版本：v1.10.32 之后（未发布批次）
> 来源：用户反馈「OPPO 手机无法扫描到本地文件」，功能定位为**卡片库**（授权库目录后库为空，无报错）

## 1. 现象

- 设置页 → 「选择库目录」→ 系统文件夹选择器授权成功 → 提示 **「已授权库目录 · 扫描到 0 张」**
- 库页停留在授权引导页，无任何错误提示；重新授权同一目录结果不变
- 同一目录在其他机型可正常扫出卡片

## 2. 排查结论（按可能性排序）

扫描链路：`SettingsView.handlePickFolder` → `android.js selectFolder/rescanLibrary` →
`LibraryFsPlugin.scanStart` → `buildScanResult` → `buildRelIndex` → `buildScanOutputFromIndex` → `scanNext` 分块回传。

### ① 扫描空结果被当作「成功」，真实原因被吞掉（直接造成"无报错的 0 张"）

`buildRelIndex()` 用 `ContentResolver.query(buildChildDocumentsUriUsingTree(...), null, ...)` 枚举子项，旧代码有两条**静默丢数据**分支：

```java
cursor = ...query(childrenUri, null, null, null, null);
if (cursor == null) continue;                        // 整个目录被跳过,不计数、不报错
int idxId = cursor.getColumnIndex(COLUMN_DOCUMENT_ID);
...
if (childDocId == null || name == null) continue;    // provider 没给 document_id → 全部子项被跳过
```

只要所选目录的 provider **不返回 children 游标**或**不带 document_id 列**（第三方/ROM 自有文件选择器常见），
整棵树会枚举出 0 个子项，而 `buildScanResult` 返回 `null`（成功）→ 界面显示「扫描到 0 张」。
**根因：失败与"空目录"无法区分，且没有任何可执行提示。**

`null` 投影（"取全部列"）是这条链路的放大器：provider 有权只回它认为必要的列，`document_id` 并不保证存在。

### ② 并发扫描共用一个全局游标 → 先发起的一方拿到空数组

```java
private volatile List<JSObject> scanResultCache = ...;   // 全局唯一
private final AtomicInteger scanCursor = ...;            // 全局唯一
```

`scanNext` 注释即写明「天然支持单消费者」。但实际会并发的入口有三个：

| 入口 | 调用 |
| --- | --- |
| 设置页挂载 | `SettingsView.refreshStats()` → `rescanLibrary('/library')` |
| 库页加载/刷新 | `useMobileLibrary.loadLibrary/refresh` → `rescanLibrary` |
| 后台增量校验 | `reconcileLibraryInBackground()` → `rescanLibrary` |

后一次 `scanStart` 会把 `scanCursor` 清零并替换 `scanResultCache`。此时先发起的消费者再调 `scanNext`
会读到新会话的游标位置（可能已到底）→ `done: true` + `files: []` → **该次 rescan 返回 0 个文件**。
慢存储 / 大卡库（OPPO 上枚举+读取耗时更长）会显著放大这个窗口。

### ③ 受限路径结构性不可读（Android 11+ 系统限制）——**真机补充信息后确认为主因**

用户补充：OPPO 上「完全读不到酒馆文件」，此前用 **MT管理器** 才能读到；自己开了开发者模式、试过各种授权仍不行，
被告知只能"下个副本"。⇒ 酒馆数据目录在 **`/storage/emulated/0/Android/data/<酒馆包名>/files/…`**。

官方文档（[Manage all files on a storage device](https://developer.android.com/training/data-storage/manage-all-files)）明确：

> Write access to all internal storage directories except `/Android/data/`, `/sdcard/Android`, and most
> subdirectories of `/sdcard/Android`. **Apps that are granted this permission still can't access the
> app-specific directories that belong to other apps**, because these directories appear as subdirectories
> of `Android/data/`.

结论：**SAF 目录授权拿不到它，`MANAGE_EXTERNAL_STORAGE`（"所有文件访问权限"）同样拿不到**。
系统层面能进 `Android/data` 的只有 root、Shizuku / adb shell（MT管理器读到的就是这条路）、
或持有系统特权的文件管理器。因此这不是本 App 的权限申请问题，**权限路线无解**，只能：

1. 酒馆侧把数据目录改到公共目录（`Android/media/…` 属共享存储，可读；或 `/sdcard/SillyTavern`）；
2. 先把 `characters/` 复制成副本到公共目录（MT管理器/系统文件管理/adb pull），再授权副本目录；
3. 本 App 若要做「直读 Android/data」，只能集成 Shizuku（借 adb 权限跑 shell 进程）。

UI 侧已能识别该路径并给出上述可执行提示（见 3.1-2）。

### ④ 与项目架构的关系：这不是「读酒馆目录」的问题

本 App 的模型（与桌面版一致）是两个角色分离的目录：

| 角色 | 说明 | 实现 |
| --- | --- | --- |
| **卡库目录** | 用户 SAF 授权、App 全权读写的目录（唯一数据源） | `LibraryFsPlugin` SAF 树 |
| **推送目标** | 酒馆 API（`POST /api/characters/import`）或另一个可写目录 | `pushToTavern` / `copyToFolder`（详情页「推送到目标」） |

桌面版能「与酒馆共用同一份目录」，是因为 Windows 上 `data/default-user/characters` 可以直接读写
（`tavern:pushDir` 走物理拷贝）。Android 上酒馆 App 的 `characters` 在 `Android/data` 内，**共用同一份目录这条前提不成立**。
因此 Android 版的正确用法是「独立卡库 + 推送同步」，**不是**去读酒馆私有目录。

⇒ 结论：不为「直读 Android/data」做任何功能（Shizuku / 分享导入 / 自动搬卡都不做）；
App 侧只负责把这条边界讲清楚，把用户引到「独立卡库 + 导入/推送」的既有能力上。

## 3. 修复内容

### 3.1 原生（`LibraryFsPlugin.java`）

1. **显式投影 + 失败降级**：子项查询改为固定列 `DOC_CHILD_PROJECTION`
   （`document_id / display_name / mime_type / size / last_modified`）；
   游标为 `null`、或缺 `document_id / display_name` 列时**主动抛异常**进入既有 `listFiles()` 降级分支
   （原分支只能靠异常触发，静默 `continue` 永远走不到），并对降级分支补 `null` 保护与 `getDocumentId` 容错。
2. **0 结果归因**：`buildRelIndex()` 返回统计 `{遍历目录数, 读到子项行数, 失败目录数}`，
   新增 `buildScanHint()`：
   - 路径在 `Android/data`、`Android/obb`、`Android` 下 → 明确提示系统限制与正确放置位置；
   - 子项查询全部失败（`queryFailures > 0 && rowsSeen == 0`）→ 提示换目录或重新授权；
   - 真正空目录 → 不产生提示，保持原有「扫描到 0 张」行为。
   `scan` / `scanStart` 返回 `hint` 字段，并通过 `Log.i("Perf", "scan empty: dirs=… rows=… fails=…")` 落日志。
3. **scanId 会话隔离**：`scanStart` 生成 `scanId` 并登记 `ScanSession`（独立游标），
   `scanNext` 按 `scanId` 取块（不带 `scanId` 时退回全局缓存，兼容旧调用）；会话 3 分钟 TTL 自动清理。

### 3.2 渲染层

- `android.js rescanLibrary()`：透传 `scanId`；0 文件且原生给出 `hint` 时以 `error` 返回，
  设置页不再弹「扫描到 0 张」的成功提示，库页也不再显示"尚未授权"。
- `CardLibraryView.vue`：新增 `libError` 计算属性（排除首次使用的「尚未选择库目录」），
  授权引导页优先展示具体原因，标题显示「库目录读取失败」。
