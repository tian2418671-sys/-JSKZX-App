## 一、用户反馈三问题 · 实测结论

### 1. 查重弹窗无法关闭 —— ✅ 已修复并实测验证

**根因**：`DedupeModal.vue` 第 9、13 行在模板裸用 `emit(...)`，但该组件是 Options API `setup()` 写法（非 `<script setup>`），`emit` 不在模板作用域 → 点击关闭按钮/覆盖层全部抛错，弹窗永无法关闭（BUG-16 只修了父组件 v-model，未发现子组件模板问题）。

**修复**：两处 `emit(` → `$emit(`。

**实测**（CDP）：点击更多 → 查重 → 弹窗打开 → 点击 X 关闭按钮 → `popup display=none`（关闭成功）✅

### 2. 查重功能不完全 / 错误 / 加载慢 —— ⚠️ 部分确认，代码侧有优化空间

**实测结果**：
- **同名查重正常**：弹窗打开即运行，出结果（如 `5513（异种思维测试）.png` 2 版本、`召唤世界…json` 2 版本，含推荐保留/完全一致/对比/清此版操作）✅
- **内容指纹查重导致 renderer 崩溃**：点"内容指纹"后全量水合 4989 张卡（`读取卡片 106/4989…`），**Chromium renderer 进程被杀 → App 崩溃**（`crashpad_client_linux.cc: Render process crash`）。这是**模拟器内存限制**（默认 2GB，WebView renderer 承载 4989 卡 chara 水合不够）
- **大量 `无内嵌角色卡数据`** 错误：测试库很多 PNG 无 chara 文本块（readCharaBatch 返回失败），这些卡参与不了内容指纹查重 → 用户感知"查重不完全"
- **加载慢根因**：内容指纹查重走 `loadCardsFullDataBatch` 全量水合；签名缓存（E2）**已在代码中**（`loadContentSigs/getContentSig/setContentSig`，`needCompute = items.filter(!getContentSig)`），首次查重需全量、二次查重秒级——但模拟器首次全量即 OOM

**代码侧可优化点（未做，列入待办）**：
- 无内嵌数据的卡应跳过（失败卡不阻塞/不重试）
- 内容指纹首次全量水合应在低内存场景分批更细/提示内存风险
- 查重运行中允许取消（已有 busyKey 概念，未完整实现取消）

### 3. 主题功能变化不大 / 无效果 / 无动画 —— 🔴 发现 1 个真实 bug（已修复），视觉增强待 P2

**实测根因（代码 bug）**：`theme.js` applyTheme 第 120 行 `root.classList.remove('theme-transition', 'theme-switching')` 在 **View Transitions 分支之前无条件执行**——模拟器 WebView 不支持 `document.startViewTransition`（Chromium < 111 或 WebView 限制）→ 走到降级路径时 CSS transition 类**已被移除** → 主题切换**完全无动画**，用户感知"没效果"。

**修复**（已完成）：applyTheme 重构——VT 分支内才移除 CSS transition；降级路径恢复 `theme-transition` + `theme-switching` 类（保留原有切换过渡动画）。

**未完成（视觉增强，待 P2）**：
- 语义色板重构已完成（8 主题 `--color-*` 变量 + `--van-*` 引用 + color-scheme 逐主题），但这是**内部结构**优化——用户可见的外观变化需要 P2 的"图标/装饰/动效"增强才明显
- 渐变装饰层（P0b）视觉密度较低（opacity 0.03-0.12），赛博朋克/未来主题的原 blur 特效换成渐变后"特效感"下降——需设计确认
- 主题切换动效（View Transitions）在模拟器 WebView 上不生效（降级 CSS transition 已修复），真机 Chromium 111+ 才能体验平滑过渡

## 五、2026-09-19 补充：内容指纹查重内存优化

**背景**：v1.10.29 实测「内容指纹查重 → 4989 卡 renderer OOM 崩溃」。根因二：
1. `loadCardsFullDataBatch` 全量水合后保留全库 Map（4989 卡完整数据常驻）；
2. PNG 个别无 chara 文本块 → 回退 `readBuffer` 整图 base64（数十 MB/张 过桥）。

**修复**（`useMobileLibrary.js` 新增 `loadContentTextsStream`，`DedupeModal.vue` 改用）：
- **流式水合**：每批（24 卡）解析完立即 `onBatch` 回调，调用方算完签名即丢弃对象 → 内存峰值 ≈ 一批，而非全库；
- **无内嵌数据卡跳过**：PNG 无 chara 文本块直接跳过，**不再回退 `readBuffer` 整图**（内容指纹只需文本，整图无意义，是 OOM 主源）；
- **可取消**：`scanCancelFlag` 令牌 + 「取消扫描」按钮，批间/批内中止，已算签名持久化保留（下次续扫跳过）；
- **二次查重保持零水合**：已有签名卡直接复用缓存进聚类，`needCompute` 仅含未算卡；
- **性能**：`itemByPath`/`idxByPath` Map 预建索引，5000 卡下避免每卡 O(n) find/indexOf。

**验证**：`npm test` 142 全绿；`npm run build:web` 构建成功。模拟器 OOM 回归待环境就绪（见待办）。
