- 日期：2026-09-18
- 版本：v1.10.28（versionCode 33，debug 包）
- 设备：JSKZX_Test 模拟器（Android 15 / API 35）
- 应用：`com.sillytavern.cardmanager.android`

## 一、问题（v1.10.27 发布验收时发现）

| # | 现象 | 根因 |
| --- | --- | --- |
| 1 | 设置页「关于 → 版本」写死 `v1.10.23`，与实际安装版本不符 | `SettingsView.vue` 模板硬编码字符串 |
| 2 | 已是最新版本时点「检查更新」仍弹「发现新版本」（OTA 链路实测中发现） | 原生 `UpdatePlugin` 只判断“发布源存在版本”（`callBase` 恒 `update:true`），不在任何层做版本比较 |

## 二、修复（v1.10.28）

1. **构建期版本注入**：`vite.config.mjs` 读 `package.json` → `define: __APP_VERSION__`；`SettingsView.vue` 动态显示（`v{{版本}} (移动端)`）。此后发版只需 bump `package.json`（与 `build.gradle` 同步）。
2. **更新比较**：`SettingsView.checkUpdate` 增加语义化版本比较 `cmpVersion(feed, 当前版本) <= 0 → 「当前已是最新版本」`；只有确实有新版本才弹升级框。
3. **发布硬校验**：`FEATURE_MARKERS` 新增 `{ key: '更新提示版本比较', marker: '当前已是最新版本' }`。

## 四、备注

- 真机旧版本（如 1.10.26）升级路径：点「检查更新」→ 检测到 1.10.28 > 当前 → 正常弹升级框（比较逻辑 `1.10.28 vs 1.10.26 = 1`）。
- 版本比较只解析数字段（忽略预发布标记），对当前 `x.y.z` 版本号方案足够。
