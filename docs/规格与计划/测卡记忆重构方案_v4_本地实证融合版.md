### 0.4 本地三个未跟踪模块的定位（v4 吸收什么、放弃什么）

| 模块 | 价值 | 问题 | v4 处置 |
|---|---|---|---|
| `useChatMemoryConfig.js` | 模型开关 + 设备检测 + 性能预算的**框架**设计合理 | `ensureModelLoaded()` 是**空壳 TODO**；无实际 ONNX 加载 | **吸收框架**，模型本体留 P3；P0 先让开关可用（开关壳 + 降级提示） |
| `useChatMemoryStore.js` | Map\<cardId, ctx\> 换卡即换记忆的**概念**正确 | 依赖 4 个**不存在的 API**（memoryGetContext/memorySaveContext/memoryClearByCard/memoryBackup）；`exportMemory` 重复定义两次 | **放弃实现，吸收概念**：v4 用现有 memoryAdd/search/list + `card.value.path` 实现同样的"换卡=换记忆" |
| `useChatFactExtractor.js` | 提取规则质量明显更高：7 领域分类、confidence、值长限制 | 有重复规则（"记住|记下"出现两次）、FALLBACK_RULES 有 `[:：]\s*(.+)` 过宽规则；仍是纯正则无模型 | **融合进 D3** 作为新规则集；修剪瑕疵后用单测锁定 |

## 二、分阶段方案

### P0 · 数据治理（对齐 v3 最小因果链，全部落地本地）

#### D1 卡级隔离（用户需求 ② 的核心）

**现状**：`MemoryPlugin.search` 无卡过滤；记录传显示名。

**改动**：

1. **原生层 `MemoryPlugin.search` 增加 `cardName` 参数**：
   ```java
   String cardName = call.getString("cardName", "");
   // scope 之后追加：card_name = ?（空串则不限制，供查看器全库浏览用）
   if (!cardName.isEmpty()) { scope += " AND card_name = ?"; args.add(cardName); }
   ```
   同时建索引：`CREATE INDEX IF NOT EXISTS idx_mem_card ON memory_items(card_name, type)`（放 `onCreate` + `onUpgrade`）。

2. **JS 层 `searchMemory(query, limit, cardName)`**：透传 cardName；`buildMemoryContext(query, cardName)` 增加参数。

3. **`CardDetailView.vue` 注入调用**（2256/2303 两处）：`buildMemoryContext(lastUserText, card.value.path)`。

4. **记录分桶改 path**（2377-2380）：`card.value.path` 替代 `card.value.name`。
   - 兼容策略：原生 `add` 时若 `card_name` 以 `记忆的旧显示名` 存在但 path 不存在，可先走迁移（见第七章）。

5. **查看器按卡过滤**（TestSidebar）：`refreshMemoryList` 增加 `cardName` 参数透传 `api.memoryList`；`memoryList` 增加 `cardName` 支持（list 原生层加同款条件）。
   - TestSidebar 需新增 prop `currentCardPath`，由 CardDetailView 传入。

**D1a 路径变更钩子**：`renameCardTo` / `moveCardToGroup` / `removeCard`（`useMobileLibrary.js:1129/1157/1174`）挂接记忆迁移：rename/move → `UPDATE memory_items SET card_name = 新path WHERE card_name = 旧path`；remove → `DELETE`。新增桥接 `memoryMigrateCard({ from, to })`。

#### D2 检索治理（修 F2/F3）

**改动**：

1. **停用词表过滤**（JS 层，`useChatMemory.js` 新增 `STOP_WORDS`）：过滤"我/你/的/了/是/在/吗/呢/啊/吧/继续/好/嗯…"等。
2. **有效词 <2 降级**：`searchMemory` 收到降级信号时改为 `MemoryPlugin.search({ query:'', cardName, limit })`（空 query + 卡过滤 = 当前卡最近 N 条，N = I2 条数），**不再有全卡返回**（原生层空 query 分支也必须带上 cardName）。
3. **修 `AND ()` 隐患**：`MemoryPlugin.search` 的切词若为空数组，直接走降级分支，不拼 `AND ()`。

#### D3 事实规则收紧（用户反馈"记录不必要数据"的核心）

**改动**：用 `useChatFactExtractor.js` 的规则面 + 关键纪律替换 `FACT_RULES`：

1. **统一走新规则集**（保留原 key 命名：名字/喜欢/讨厌/年龄/位置/目标/备忘，与现有记忆查看器兼容；新增 职业/性别/关系/家人/食物偏好/过敏/健康，值上限 30 字）。
2. **显式指示词放宽**："请记住/记住/我叫/我今年"等显式路径值上限 80 字（v3 D3 口径）。
3. **排除语气**：疑问句（？）、否定假设（"如果/要是/假如"）、引用（"他说…"）不提取。
4. **单测锁定**：`test/` 新增"我在思考…"应返回空、"我的想法是…"应返回空 的回归用例（对齐 v3 验收）。

#### D4 同 key 覆盖更新（修 F6）

**改动**：`MemoryPlugin.add`：
- fact 型写入前查 `key + card_name` 冲突；冲突则 `UPDATE content=新值`（保留首次 `created_at`）而非插入。
- 兜底：message 型维持现状（每卡 40 条修剪）；summary 型无写入调用，不动。

#### I2 注入上限（可配置）

**现状**：`getMemoryLimit()` 上限已钳到 200，默认 20。

**改动**：默认改为 **8 条**（`jsmobile-memory-limit` 默认值从 20 → 8）；新增 token 预算 `jsmobile-memory-inject-tokens` 默认 200，`buildMemoryContext` 按"条数 + 估算 token"双约束截断（tokenEstimate 现有工具可复用）。`setMemoryLimit` 钳制范围保持 1-200。

#### I4 注入格式 C（修 F10）

**改动**：`buildMemoryContext` 输出从 Markdown 表格改为：

```
<memory>
<user_profile>
  名字：星野
  喜好：红色的花
</user_profile>
<recent_events>
- 星野在图书馆遇到主角
</recent_events>
</memory>
```

- 空记忆整体跳过（facts 与 summaries 均空 → 返回 ''）。
- 截断先于转义。
- 双写开关：`jsmobile-memory-format`（C / markdown）默认 C，P1 设置页下拉。

#### I5 注入 debug（简化落地）

**改动**：测卡页新增强制可读的信息块（不依赖完整 debug 面板）：
- 每次注入后在 `TestSidebar` 记忆区显示：注入几条 / 来源卡 path / 降级与否（"最近 N 条" or "关键词命中"）/ 估算 token。
- 实现：`buildMemoryContext` 返回 `{ text, meta }`，meta 供展示。

#### B1 批量测卡抑制（两万卡场景，v3 红线）

**改动**：批量测卡入口（CardLibraryView 批量模式）进入时自动 `setMemoryEnabled(false)` 并提示；单卡测卡可手动开启。落地到批量测试的起始函数，不做全局持久化。

#### 迁移 + 灰度（临门一脚，确保 P0 可回退）

- **7.1 显示名 → path**：迁移脚本按"显示名匹配到的卡列表"分情况（唯一匹配 → 迁移；多卡同名 → 保留原 `card_name` 不动，进"遗留桶"由 D1 新写入 path 后自然隔离；无匹配 → 保留不动）。
- **7.2 schema 版本化**：`MemoryPlugin` 的 `DB_VERSION` 2 → 3（新增 `(card_name, type)` 索引 + 可选 `content_hash` 列占位），对齐 `SqliteMetaPlugin` 的 user_version 模式。
- **7.3 灰度 flag**：`jsmobile-memory-v2`（localStorage）；关闭时 `buildMemoryContext` 走旧路径（旧分桶/旧格式/旧条数）。

### P1 · 交互升级（用户需求 ③）

#### M1 记忆查看器重做（TestSidebar 记忆区）

| 现状 | v4 |
|---|---|
| 编辑/删除用 `window.prompt` | 行内编辑弹窗（van-dialog + 字段） |
| 无确认/拒绝 | **未确认的新 fact 高亮标记「待确认」**；点 ✓ 确认入库 / ✗ 拒绝删除 |
| 无右滑 | **van-swipe-cell 右滑菜单**：确认 / 编辑 / 删除 |
| 全库视角 | 顶部显示「当前卡」chip + 可切换"只看本卡 / 全部"，默认只看本卡 |

**实现**：fact 表新增 `confirmed INTEGER DEFAULT 1`（原生层 `schemav3` 迁移）；`recordFact` 写入 `confirmed=0`；注入只取 `confirmed=1`；确认/拒绝走 `memoryConfirm({ id, confirmed })` 新桥接。

#### R1/R2 记录准确度（修 F9）

- R1：user 记**原始输入**（trim），processedText 不覆盖原文（或双写，加来源标注）。
- R2：assistant 记 `msg.index` 实际选中候选（在 `nextSwipe/prefSwipe` 切换时回写记录）。

### P2 · L2 摘要落地（修 F7）

- token 预算触发 + 增量总结（chatMemos 语义），LLM 摘要可关。与 v3 R4 一致，预算 2-3 人日。

### P3 · 模型（用户需求 ① 本体）

- **复用 `useChatMemoryConfig.js` 框架**：开关（默认关）/ 设备检测 / 性能预算 / 降级提示全部保留。
- **补上真正的模型体**：
  1. embedding 模型（ONNX.js / TFLite / MediaPipe）384 维 ~20MB，加载到 IndexedDB 缓存；
  2. `extractor` 换成"规则结果 + 模型打分"双通道（低置信度规则交由模型确认）；
  3. 检索从 OR-LIKE 换成向量 topK（sqlite-vec 或内存 ANN）。
- **降级链**：模型不可用 → 规则提取 + 关键词检索（P0 能力），全程不阻塞测卡。

## 五、验收标准

| 项 | 判定 |
|---|---|
| 跨卡污染 | 测卡 A 会话注入记忆全部来自卡 A（查看器按卡看可证） |
| 误吞 | "我在思考…"/"我的想法是…"不再产生 fact（单测 + 实机） |
| 膨胀 | 同 key 只保留最新（D4）；注入 ≤8 条且 token ≤ 配置 |
| 换卡 | 切换卡片后查看器/注入即刻切换为该卡记忆 |
| 交互 | 新 fact 出现待确认标记；右滑可确认/编辑/删除 |
| 回归 | 更新后全绿 + `jsmobile-memory-v2` 关闭走旧路径无行为变化 |
