# 移动版已知问题 · 根因与修复方案

> 本文档基于 `js/mobile/` 源码逐行核对定位，每个问题含「根因」「修复」「验收」。

---

## BUG 1：打开后屏幕不能上下滑动

### 根因
卡片详情页 `CardDetailView.vue` 使用了 Vant `van-tabs`（sticky），但样式链不完整：

- `.detail-page { flex:1; min-height:0 }`（滚动已被 flex 撑开留给 tabs）
- 只写了 `.detail-page :deep(.van-tabs__content) { flex:1; overflow-y:auto }`，**没有给 `van-tabs` 根节点设置 `flex:1; min-height:0; overflow:hidden`**
- 结果：`van-tabs` 高度由内容撑开，超出的内容被外层 `.mobile-shell{overflow:hidden}` 裁剪 → 页面看着能显示首屏，但整体**无法上下滑动**

### 修复
在 `CardDetailView.vue` `<style scoped>` 补齐高度链路：

```css
.detail-page :deep(.van-tabs) {
    flex: 1;
    min-height: 0;
    display: flex;
    flex-direction: column;
    overflow: hidden;
}
.detail-page :deep(.van-tabs__content) {
    flex: 1;
    min-height: 0;
    overflow-y: auto;
}
/* 单面板也占满，保证子滚动容器可用 */
.detail-page :deep(.van-tab__panel) {
    min-height: 100%;
}
```

同时复核其余两个「自滚动」页（世界书/设置）滚动容器均为 `.view-body{flex:1;min-height:0;overflow-y:auto}`，无 `height:100%` 陷阱（已排查 `js/mobile` 全目录，仅 `MobileCardCover.vue` 一处图片 `height:100%`，不影响滚动）。

### 验收
打开任意角色卡详情，四个 Tab 内均可上下滚动；长列表（世界书条目多时）顺畅滑动到底。

## BUG 2：角色卡打开后读取不到世界书数据

### 根因
`CardDetailView.vue` 的 `wbEntries` computed 与 `WorldbookView.vue` 的 `openFileWb` 只认一种世界书形态：

```js
// CardDetailView.vue L291-300
const wb = d.value.extensions.world_book;
if (!wb.entries) wb.entries = {};
return wb.entries;
```

而真实卡片世界书存在多种脏形态（桌面端已用 `extractBookEntries` 根治，见 `js/utils/cardLoader.js` L42-67）：
1. `character_book` 直接在顶层（老 V1 卡）——移动端完全没读这个字段
2. `extensions.world_book.entries` 是**数组**——`wb.entries` 拿到数组，模板按对象字典渲染出错
3. `entries` 字典对象——仅有此形态目前能显示

### 修复
两处统一改用 `extractBookEntries`（已是纯函数导出，数组优先识别 → entries 数组 → 字典 `Object.values`，永不抛错）：

```js
// CardDetailView.vue
import { extractBookEntries } from '../../utils/cardLoader.js';

const wbEntries = computed({
    get() {
        const book = d.value.extensions?.world_book ?? d.value.character_book ?? null;
        return extractBookEntries(book);
    },
    set(/* 回写：保持原容器结构 */) {}
});
// 模板 v-for 改为数组形态：(e, i) in wbEntries
// removeWbEntry/添加条目：在数组中 splice/push，同时同步原容器
```

`WorldbookView.vue` 的 `openFileWb`：`entries: extractBookEntries(wb.wb)`；`saveAll` 回写时保持 wrapped 结构。

### 验收
打开 V1 卡（顶层 `character_book`）、数组 entries 卡、字典 entries 卡，世界书 Tab 均能正确列出条目；增删改保存后回读一致。

## BUG 3：世界书功能界面与桌面版不符

### 根因
`WorldbookView.vue` 顶部有「卡内世界书」分组（`cardWithWb` 渲染角色卡内嵌世界书），把两种世界书混在同页；且页面名是「世界书」而非独立的世界书库形态；无任何导入能力。

### 修复（对齐桌面版世界书库 = 独立世界书）
1. **移除「卡内世界书」区块**：删除 `cardWithWb`、`openCardWb` 及相关模板（卡内世界书只在角色卡详情页编辑，桌面版如此）。
2. **改名**：`MobileApp.vue` Tab `to="/worldbook"` 文案「世界书」→「世界书库」，保持与角色卡库同级。
3. **增加导入能力**（等价桌面版「文件夹扫描导入 / JSONL 导入 / 直链导入」）：
   - 扩展桥接：`android.js`/`LibraryFsPlugin.scanFolder` 支持 `ext:'.json'`（当前仅 `.png`，见 `scanTargetFolder`），扫描目录中的世界书 JSON 文件，过滤出含 `entries` 特征的文件（复用 `extractBookEntries` 判断），经 `createWorldbook` 复制入库。
   - JSONL 批量导入：世界书库页 `<input type="file" accept=".jsonl">` → `readText` → 逐条解析 → `createWorldbook` 入库。
   - 直链导入：复用 `api.fetchWbUrl(url)`（方案 9）。
4. 顶部工具栏：批量导出（`exportWorldbooksBatch`）、查重保留。

### 验收
世界书库页只显示独立世界书文件；可文件夹扫描导入/JSONL 导入/直链导入；改名后 Tab 显示「世界书库」。

## BUG 4：角色卡打开后很多条目不能折叠

### 根因
`CardDetailView.vue` 世界书 Tab 与正则 Tab 的条目（`.wb-item` / `.regex-item`）全部**平铺展开**展示 content/正则正文，条目多时列表极长且无法收起；「高级设定/状态栏预览」虽有 `van-collapse` 但入口较弱，用户找不到折叠能力。

### 修复
1. 世界书条目卡改为**可折叠面板**：头行（enabled 开关 + comment + 删除）始终显示；点击头行展开/收起正文（`content` 文本域）。每个条目维护 `collapsed` 状态：
   ```html
   <div class="wb-item" :class="{ folded: isFolded(key) }" @click="toggleFold(key)">
       <div class="wb-head">…开关/名称/箭头…</div>
       <template v-if="!isFolded(key)"><van-field v-model="e.content" … /></template>
   </div>
   ```
2. 正则条目同样处理：默认只显示 `enabled/scriptName`，正文（findRegex/replaceString）点击展开。
3. 「高级设定」折叠块首屏默认展开一个，保持文案提示「点击收起」。

### 验收
条目多时默认紧凑，点击头部可逐条展开/收起，无整页高度爆炸；保存与展开状态互不影响。

## BUG 5：设置界面出现乱码

### 根因（已排除项 + 最可能项）
已排查并排除：所有 `.vue` 源文件均为 UTF-8、`index.html` 已声明 `<meta charset="UTF-8">`、js/mobile 无损坏字符。

最可能：**浅色背景 + 未生效主题时文字/图标对比失衡**，及 `✓`/`·`/`…` 等特殊字符在部分安卓 WebView 字体下渲染为方块；另需确认 Vant 图标字体（`@vant/icons` 的 woff/ttf）被 Vite 正确打进 `web/`——字体缺失时 `van-icon` 会显示为占位方块，设置页图标最密集。

### 修复
1. **统一样式字体栈**：`css/style.css` 全局 `font-family` 保留微软雅黑回退即可，移动端再覆盖：
   ```css
   .mobile-shell { font-family: -apple-system, "PingFang SC", "HarmonyOS Sans SC",
        "Noto Sans SC", "Microsoft YaHei", sans-serif; }
   ```
2. **特殊字符替换**：设置页 `✓`、`·`、`…` 一律改为常规文本（`已授权`、`-`、`...`），或保留但在 CSS 中指定 fallback 字体。
3. **验证图标字体入包**：检查 `web/assets` 是否含 vant 字体文件；若无，在 `vite.config.mjs` 对 `@vant/icons`（或 `vant`）关闭 `inlineDynamicImports`/确认 assetsInlineLimit 处理。
4. 真机复现时截图确认位置（比对 BUG 6 修复后浅深主题下的观感），若仍是乱码字符，抓取 `web/` 产物对应 chunk 对照源码编码。

### 验收
设置页所有文字/图标正常显示，无方块、无乱码；浅深主题下均可读。

## BUG 6：主题切换没有效果

### 根因（已确认）
`js/mobile/theme.js` 的 `applyTheme` 只在 `<html>` 添加 `theme-dark`/`dark` 两个 class，但：

- **全项目没有任何 CSS 定义 `.theme-dark { --van-xxx: … }` 变量覆盖**（grep 确认仅 theme.js 3 处引用）
- Vant 组件配色全部走 `--van-*` CSS 变量，从未被修改 → 切到深色只变了 body 背景色，组件全是浅色
- Tailwind `dark:` 变体在移动端视图基本未使用，`dark` 类也无样式定义

### 修复
新增移动端全局主题样式（在 `entry.js` 移动端分支引入，或 `css/style.css` 末尾追加）：

```css
/* 移动端深色 = html.theme-dark 覆盖 Vant 全套变量 */
html.theme-dark {
    --van-background: #101014;
    --van-background-2: #1b1c22;
    --van-text-color: #e4e4e7;
    --van-text-color-2: #a1a1aa;
    --van-gray-1: #1b1c22;
    --van-gray-2: #26272e;
    --van-gray-3: #34363f;
    --van-gray-5: #52525b;
    --van-gray-6: #8b8b95;
    --van-border-color: #34363f;
    --van-cell-background: #1b1c22;
    --van-cell-group-background: transparent;
    --van-popup-background: #16171c;
    --van-nav-bar-background: #16171c;
    --van-tabbar-background: #16171c;
    --van-field-background: transparent;
    --van-field-input-text-color: #e4e4e7;
    --van-button-default-background: #26272e;
    --van-button-default-border-color: #34363f;
    --van-action-sheet-background: #16171c;
    --van-empty-description-color: #8b8b95;
}
```

（变量清单以 `vant/lib/index.css` 中实际使用的为准，可整段覆盖；设置页「深色主题」开关的逻辑本身已正确，无需改动。）

### 验收
开启深色后：全部 Vant 组件（导航栏/TabBar/单元格/弹窗/气泡/加载骨架）整体变深，切换即时生效且重启记住选择；系统栏图标颜色同步切换。

## BUG 7：聊天界面渲染功能缺失、文字对比不明显

### 根因
`CardDetailView.vue` 测卡 Tab 目前为纯文本气泡（`<pre class="b-content">`），无渲染模式；气泡样式 `.bubble.user` 青色（`#06b6d4`）+ 白字，`.bubble.assistant` 白底灰字，在深色/浅色背景下区分度弱、AI 回复文字不突出。

### 修复
1. **渲染模式开关**：测卡工具栏加「渲染」开关，开启后 AI 气泡走 `v-html`（DOMPurify 清洗，`dompurify` 已在依赖中）：
   ```js
   import DOMPurify from 'dompurify';
   const renderHtml = (s) => DOMPurify.sanitize(s, { ADD_ATTR: ['target'], ADD_TAG: ['img', 'table', 'tr', 'td'] });
   // 模板：<div class="b-content" :class="{ rich: chatRenderMode }"
   //        :dangerously-... 使用 v-html 前先清洗
   ```
2. **文字对比增强**（浅/深双主题生效）：
   - 用户气泡：深主题下用 `--van-primary-color`（保持青色），文字纯白加粗，增大字号 `15px`、行高 `1.7`
   - AI 气泡：白底加 1px 边框（深主题 `--van-background-2` + `--van-border-color`），`b-name` 用主题色标签（如「角色名」前坠 ●）
   - 消息姓名行改为彩色小徽标，区分「我 / 角色名」
   - 输入框文字/placeholder 颜色接入主题变量
3. 渲染模式开启时清空按钮/输入提示保持可用；渲染失败回退纯文本。

### 验收
切换渲染开关后：AI 回复中 HTML/表格/图片按渲染展示且无 XSS 执行；浅深主题下用户与 AI 气泡边界清晰、文字对比明显。
